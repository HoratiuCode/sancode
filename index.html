SanCode is a coding standard for AI agents designed to reduce AI-generated code bloat, unnecessary abstractions, and dependency addiction. Its core rule is simple: every line of code must justify its existence.

$ curl -fsSL https://raw.githubusercontent.com/HoratiuCode/sancode/main/install.sh | sh

Finds Claude Code, Hermes, and OpenClaw and installs the skill into each. No package. No runtime.

SanCode is not software you install. It is pressure you apply to AI agents before they bury your startup in code nobody asked for.

A brain, not a prompt

Install SanCode as one skill for Claude Code, Hermes, OpenClaw, Claude chat, or Cowork. On first run it asks your rules and how you like to work. Then it remembers your project in one Markdown file, routes every task to the right mode, and gets sharper each time it ships.

Coding Mode

The default brain. Delete before create, native before package, one file before architecture. Runs on every task.

Startup Mode

Asks whether it should be built at all. Returns BUILD, VALIDATE FIRST, or DON’T BUILD, plus a next step under 48 hours.

Council Mode

At a real fork, six seats argue, vote, and return one decision with a kill-switch. Convenes itself before new packages, rewrites, or infrastructure.

every task
0 Setup   # first run: asks your rules and way of coding
1 Recall  # read brain.md, check what happened to past code
2 Route   # coding, startup, or council
3 Act     # smallest working change
4 Score   # measured from git diff, not guessed
5 Learn   # keep only what changes the next decision

Principles

Delete Before Create

First look for code to remove, reuse, or collapse. New files are a last resort, not a reflex.

Native Before Package

Use browser APIs, framework defaults, SQL, the filesystem, and the standard library before adding another dependency.

Simple Before Abstract

One known use case does not need providers, managers, adapters, event buses, factories, or architecture theater.

Single File Before Architecture

Keep behavior close together until separation makes the current code easier to understand.

Working Before Perfect

Ship the path users need now. Polish internals after usage proves the feature deserves more time.

Revenue Before Scale

Validate demand, charge money, and talk to users before preparing infrastructure for imaginary traffic.

Decision Tree

Does this already exist? Can I reuse it? Can I simplify it? Can I remove it? Will users care? Will users pay? Can I launch today?

Startup Mode

Before building, ask whether the idea can be validated without code, sold before development, or tested with a manual workflow this week.

Work Mode

For everything that isn’t code, in Claude chat and Cowork: answer first, one page before a deck, reuse the existing doc, no new tools for a one-time job.

Council Mode

At a real fork (new dependency, rewrite, build vs buy, ship vs polish), six seats argue, vote, and return one decision with a kill-switch and a first move. Call it with "council mode".

Model Routing

Every task is rated easy, normal, or hard. SanCode suggests /model haiku for a typo and /model opus for a migration, or in Claude Code hands the hard part to an Opus subagent. Codex gets one-line profile suggestions.

Infrastructure Mode

Before adding Redis, Kubernetes, microservices, queues, workers, or search clusters, prove SQLite, cron, native search, and a single server cannot handle the current product.

SanScore

Every task ends with a score out of 100 based on packages added, files created, lines written, complexity introduced, and infrastructure added. Higher means simpler.
